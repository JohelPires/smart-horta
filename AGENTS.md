# AGENTS.md

ESP32 smart-gardening controller: reads soil/water/climate sensors, drives
irrigation valves, publishes telemetry to a computer/Raspberry Pi over MQTT.
Monorepo, currently being scaffolded — this file is the source of truth for
intended layout and commands.

## Stack (decided)
- Firmware: ESP-IDF (C, CMake, `idf.py`), target `esp32`.
- Simulation: Wokwi — the only option that emulates ESP32 WiFi + MQTT end to end.
  Renode was evaluated and rejected: it has no ESP32 SoC model (only a generic
  `xtensa-sample-controller`); QEMU runs ESP-IDF but has no WiFi.
- Host/RPi: Python + MQTT (`paho-mqtt`), broker = Mosquitto.

## Layout (target)
- `firmware/` — ESP-IDF project: `CMakeLists.txt`, `sdkconfig.defaults`,
  `main/`, `components/` (hal, sensors, irrigation, mqtt), `wokwi.toml`,
  `diagram.json`, `chips/`.
- `host/` — Python package: MQTT subscriber, storage, dashboard/CLI.
- `docs/` — wiring, calibration, MQTT topic reference.

## Commands
Firmware (run from `firmware/`; source ESP-IDF `export.sh` in each new shell):
- `idf.py set-target esp32`
- `idf.py build`                      # required before any simulation
- `idf.py -p /dev/ttyUSB0 flash monitor`
- `idf.py wokwi`                      # needs `pip install idf-wokwi` + ESP-IDF >= 6.0

Host:
- `python -m venv .venv && source .venv/bin/activate`
- `pip install -r host/requirements.txt`
- Broker: `mosquitto -c emulation/mosquitto.conf -v`
- Run: `python -m host.main`
- Tests: `pytest host/`   (single: `pytest host/tests/test_x.py::test_name`)

## Wokwi usage
- Config lives in `firmware/wokwi.toml` + `firmware/diagram.json` (commit both).
- `wokwi.toml` for ESP-IDF:
  `firmware = 'build/flasher_args.json'` (generated by `idf.py build`),
  `elf = 'build/smart_horta.elf'`.
- Run via VS Code "Wokwi Simulator" (F1 -> Start Simulator) or CLI:
  `curl -L https://wokwi.com/ci/install.sh | sh`; `wokwi-cli init`; `wokwi-cli .`.
  Token: `WOKWI_CLI_TOKEN`. Flags: `--timeout <ms>`, `--expect-text`, `--fail-text`,
  `--serial-log-file`, `--scenario`, `--vcd-file`, `--gdb-server-port`.
- WiFi: SSID `Wokwi-GUEST`, password `""`, channel 6. Public gateway IP 10.10.0.2
  (free, outbound only). Private gateway IP 10.13.37.2 (paid, local net + incoming).
- MQTT: public broker (broker.hivemq.com / test.mosquitto.org) via Public Gateway;
  for the local Mosquitto broker run the Private IoT Gateway and use
  `host.wokwi.internal:1883`. HTTP server inside ESP32 needs the Private Gateway.
- Parts: wokwi-dht22 (use "DHT sensor library for ESPx"), wokwi-ntc-temperature-sensor,
  wokwi-potentiometer / wokwi-slide-potentiometer (analog soil-moisture proxy),
  wokwi-relay-module (pump/valve; npn = active-high), wokwi-servo, wokwi-hc-sr04.
  No native soil-moisture part: use a pot or a custom WASM chip in `chips/` (`[[chip]]`).
- Limits: no Bluetooth, no MCPWM, I2S in progress, CPU capped ~8 MHz.
  CI free tier 50 sim-min/month — keep tests short with `--timeout`/`--expect-text`.

## Constraints / gotchas
- All sensor/actuator access goes behind the `hal` component so mock/diagram parts
  and real hardware share the same application code.
- Irrigation must fail safe (valves closed) on init error or watchdog.
- `diagram.json` pin numbers must match `components/hal/include/board.h`.
- MQTT topics: `horta/<device_id>/telemetry`, `horta/<device_id>/cmd`.
- Do not commit generated `sdkconfig`; keep defaults in `sdkconfig.defaults`.

## Verify before claiming done
- `idf.py build` clean, then start the Wokwi sim and confirm boot logs / WiFi connect.
- `pytest host/` passes.
